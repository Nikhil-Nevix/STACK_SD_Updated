SECTION 6 — AI & INTELLIGENCE ENGINE
════════════════════════════════════════════════════════════

6.1 CONFIDENCE SCORER (confidence_scorer.py)
Calculate confidence score 0-100% using 4 weighted factors:

  Factor 1 — Intent Clarity (weight: 30%)
    Score based on how clearly GPT-4o understood the intent
    Use GPT-4o to return a clarity score 0-1 with reasoning

  Factor 2 — SOP Match (weight: 35%)
    Score = cosine similarity between ticket embedding and 
    best matching SOP embedding from pgvector
    Normalize to 0-100

  Factor 3 — Historical Success (weight: 25%)
    Query ai_resolutions table:
    success_rate = (successful auto_resolutions for same use_case) 
                   / (total auto_resolutions for same use_case)
    Default to 0.7 if no history

  Factor 4 — Input Completeness (weight: 10%)
    Check required fields per use case:
    sharepoint: [site_url, request_type, user_email]
    license: [license_type, user_email, business_justification]
    dl_update: [dl_name, action_type, user_email]
    windows: [device_name, issue_type, user_id]
    Score = fields_present / total_required_fields

  Final score = (clarity*0.30) + (sop*0.35) + (history*0.25) 
                + (completeness*0.10)

  Decision:
    >= threshold.auto_resolve_min → decision: auto_resolve
    >= threshold.review_after_min → decision: review_after  
    < threshold.review_after_min  → decision: escalate

6.2 RAG PIPELINE (rag_pipeline.py)
  - Use Azure OpenAI text-embedding-3-large to embed ticket
  - Query pgvector with cosine similarity:
    SELECT * FROM sops 
    WHERE use_case = :use_case AND is_active = TRUE

6.4 SLA PREDICTOR (sla_predictor.py)
  Celery task runs every 5 minutes:
  For each open ticket:
    1. Get sla_deadline and current time
    2. Calculate time_remaining = sla_deadline - now()
    3. Get avg_resolution_time for this use_case from history
    4. Get current queue depth for this use_case
    5. Estimate predicted_resolution = avg_time * (1 + queue_factor)
    6. If time_remaining > predicted_resolution * 1.5 → safe
    7. If time_remaining > predicted_resolution → at_risk
    8. If time_remaining <= predicted_resolution → breached
    Update ticket.sla_status accordingly
    Log to audit_logs with event_type=sla_at_risk or sla_breached

6.5 ESCALATION ENGINE
  When decision = escalate:
    1. Get agent group for ticket.use_case
    2. Get group.assignment_mode
    3. Select agent:
       round_robin: pick next agent in rotation 
                    (track last assigned in Redis)
       first_available: query Freshservice agent availability
       priority: pick agent with lowest priority_order
    4. Datta fallback: if selected agent unavailable, 
       assign to Datta (priority_order=999)
    5. Call freshservice_service.assign_ticket(ticket_id, agent)
    6. Add ai_context note with:
       - What was attempted
       - Why it failed/confidence was low
       - Recommended next steps from SOP
       - Confidence score breakdown
    7. Update ticket status to 'escalated'
    8. Notify user via notification_service
